# Ageless Companion — Environment Setup Learning Notes

*A quick reference you can revisit whenever things feel confusing again.*

---

## 1) What Today Was Really About

You didn’t just “set up VS Code”.
You built a **reproducible runtime environment**.

In AI/ML projects, most failures happen **before the code runs** — at the environment layer.

You solved four separate systems learning to cooperate:

| Layer   | Role                         |
| ------- | ---------------------------- |
| macOS   | Operating system             |
| zsh     | Command interface (terminal) |
| conda   | Python environment manager   |
| VS Code | Project runtime launcher     |
| Python  | Program execution            |

Your project now runs in a controlled sandbox called **`ageless`**.

---

## 2) The Core Mental Models

### Environment ≠ Folder

A folder holds files.
An **environment** holds:

* Python version
* installed libraries
* compiled dependencies

Each project should have its own environment.

> One project = one environment

---

### The 3 Truth Signals (Very Important)

When debugging environments, these are **not equally reliable**:

| Signal                   | Reliability      |
| ------------------------ | ---------------- |
| Terminal prompt `(base)` | ❌ Cosmetic       |
| VS Code badge            | ⚠️ UI hint       |
| `sys.executable`         | ✅ Absolute truth |

Always verify using:

```bash
python -c "import sys; print(sys.executable)"
```

If it prints:

```
.../envs/ageless/bin/python
```

You are inside the correct environment.

---

## 3) Conda vs pip (The Confusion You Had)

They do different jobs.

| Tool             | Purpose                        |
| ---------------- | ------------------------------ |
| conda            | system + compiled dependencies |
| pip              | Python libraries               |
| requirements.txt | project dependency list        |

### Correct Pattern

* Install scientific & hardware libraries → **conda**
* Install API/SDK libraries → **pip**

### Why mixing randomly breaks things

Because compiled binaries (NumPy, SciPy, Torch) must match the Python runtime ABI.

---

## 4) What a “Wheel” Is

A wheel (`.whl`) is a **precompiled Python package**.

If pip cannot find a wheel, it tries to compile locally → errors happen.

Apple Silicon Macs especially require prebuilt binaries.
That’s why we used conda for audio & scientific packages.

---

## 5) Why VS Code Kept Forgetting the Environment

VS Code remembers interpreters **per project workspace**, not per folder.

Opening with:

```
code .
```

creates a temporary workspace.

Opening with:

```
code AgeLess_Companion.code-workspace
```

opens a persistent project.

The workspace file is the project’s identity card.

---

## 6) The macOS Problem (The Real Hidden Bug)

macOS GUI apps do **not read `.zshrc`**.

So VS Code could not see Conda’s PATH and defaulted to system Python (3.9.6).

We fixed this by exporting Conda to the macOS launch environment using:

```bash
launchctl setenv PATH "/opt/homebrew/Caskroom/miniconda/base/condabin:/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"
```

This made GUI apps aware of Conda.

---

## 7) requirements.txt — What It Actually Does

It does **nothing automatically**.
It is only a declaration of what your program needs.

Example:

```
numpy
scipy
sounddevice
```

It does NOT install anything unless you run:

```bash
pip install -r requirements.txt
```

Purpose:

* reproducibility
* GitHub sharing
* deployment
* CI/CD

---
